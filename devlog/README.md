# Dev Log

One markdown file per working day, named `YYYY-MM-DD.md`.

Each entry records:
- **What was built / changed** — files added, modified, deleted
- **Why** — the decision or requirement that drove the work
- **Key design choices** — anything that could be done differently and should be ablated/revisited
- **Open questions / next steps** — what remains before this piece is complete

---

## Convention

```
devlog/
  README.md          ← this file
  2026-10-30.md      ← first entry (weather risk layer)
  2026-11-01.md      ← next session ...
```

Keep entries factual and terse — this is a reference log, not a diary.
Paste in any important output (test results, CLI output, error messages) that
you'll want to compare against later.
